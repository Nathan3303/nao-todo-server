# 可空时间字段规范

## 为什么
当前数据库中存储可空时间字段（如 given_up_at）时，使用 `sql.NullTime` 只能表达两种状态：有值（Valid=true）和 NULL（Valid=false）。但在更新场景下，我们需要表达三种状态：
1. **不更新**：前端未传递该字段，保持数据库原有值
2. **设置为 NULL**：前端明确传递 null，将字段设为 NULL
3. **设置为具体时间**：前端传递有效的时间字符串

目前的实现无法区分"不更新"和"设置为 NULL"，导致无法正确处理前端传递的 null 值。

## 变更内容
- 创建自定义可空时间类型 `NullableTime`，支持三种状态
- 更新值对象中的时间字段类型，从 `sql.NullTime` 改为 `*NullableTime`
- 更新转换逻辑，正确处理三种状态的转换
- 更新持久化层的更新映射逻辑，支持将字段设置为 NULL

## 影响范围
- 影响的模块：所有使用可空时间字段的领域对象（任务、项目、标签等）
- 影响的文件：
  - `infrastructure/utils/`：新增 `NullableTime` 类型及转换函数
  - `domain/*/valueobjects/`：更新值对象的时间字段类型
  - `application/*/converters.go`：更新请求到值对象的转换逻辑
  - `infrastructure/persistence/*/converters.go`：更新值对象到数据库模型的转换逻辑

## 新增需求
### 需求：可空时间字段三态支持
系统 SHALL 支持可空时间字段的三种状态：不更新、设置为 NULL、设置为具体时间。

#### 场景：前端未传递时间字段
- **当** 前端更新请求中未包含时间字段
- **则** 数据库中该字段保持原值，不进行更新

#### 场景：前端传递 null
- **当** 前端更新请求中时间字段值为 null
- **则** 数据库中该字段被设置为 NULL

#### 场景：前端传递有效时间字符串
- **当** 前端更新请求中时间字段值为有效的 RFC3339 格式字符串
- **则** 数据库中该字段被设置为对应的时间值
